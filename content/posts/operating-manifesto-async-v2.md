## 1. The Asynchronous Operating Manifesto

In complex industrial automation, software engineering, and Operational Technology (OT) system architecture, real-time meetings are often an inefficient mechanism for technical decision-making. Live video calls introduce cognitive context-switching, unrecorded verbal commitments, and time-zone friction that erode engineering throughput.

We operate under a strict **Async-First, Zero-Meeting Philosophy**. 

By shifting all communication to structured written documentation, code commits, and asynchronous ticketing platforms, we provide our international B2B partners with higher technical quality, complete auditability, and uninterrupted focus on engineering deliverables.

> **Key Takeaway:** We do not offer live phone calls, video meetings, or on-site manual consultation. Every technical proposal, schema design, and code delivery is executed asynchronously in professional B2 English.

## 3. The 4-Step B2B Engagement Workflow

Our engagement process is engineered to be friction-free, structured, and entirely asynchronous from initial inquiry to final code handoff:

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                     ASYNCHRONOUS B2B ENGAGEMENT WORKFLOW                        │
└─────────────────────────────────────────────────────────────────────────────────┘

 [Step 1: Technical Screening]
  └── Partner submits project parameters via Tally.so Screening Form.
                                      │
                                      ▼
 [Step 2: Written Spec & Scope Agreement]
  └── We deliver a detailed Technical Proposal & Scope Document within 24h.
                                      │
                                      ▼
 [Step 3: Asynchronous Sprint Execution]
  └── Codebase built in private GitHub Repo; progress tracked on Jira/Slack.
                                      │
                                      ▼
 [Step 4: Handoff & Cryptographic Verification]
  └── Final delivery packaged with Docker 1-Click Setup & SHA-256 signature seal.
```

### Detailed Step Breakdown

1. **Step 1: Technical Screening Form:** The prospective partner fills out our embed Tally form, specifying PLC types, database requirements, and target scope.
2. **Step 2: Written Specification & Fixed Proposal:** Within 24 hours, we review the technical requirements and issue a comprehensive written specification, timeline, and fixed-scope pricing agreement.
3. **Step 3: Asynchronous Execution:** Engineering progress is tracked transparently via private GitHub commits and Jira tickets. Communication takes place strictly in written B2 English.
4. **Step 4: Handoff & SHA-256 Sign-off:** The deliverable is delivered as a containerized Docker package, complete with automated tests, troubleshooting guides, and a cryptographic SHA-256 verification seal.

## 4. Communication Stack & SLA Standards

To maintain rapid progress without live meetings, we adhere to strict **Service Level Agreements (SLAs)** across our asynchronous communication stack:

* **Slack / Teams Workspace (Async Channels):** Response window within **12 to 24 hours** for technical inquiries.
* **Jira / GitHub Issues:** Code reviews, bug reports, and milestone updates processed during daily **1.5h Block Time**.
* **Email & Technical Docs:** Formal scope adjustments and invoice notices delivered via written email.
* **Language Standard:** All written deliverables, code comments, and ticket communications are conducted exclusively in **Professional Technical English (B2+ level)**.

## 5. Legal Shield, NDA Anonymization & Liability Waiver

### 🔒 NDA Safety & Standard Reference Models
To protect current enterprise obligations and maintain non-compete compliance:
* We enforce a **100% Data Anonymization Protocol**. Public codebases and architecture write-ups strictly utilize **Standard Reference Models (`FAC_GLOBAL_01`)**.
* We accept **no live plant data, internal credentials, or proprietary site code** through public web forms.

### ⚠️ Liability Disclaimer & Merchant of Record
* **AI-Drafted Notice:** Codebase schemas and automation scripts are refined using an **AI Co-pilot (Human-in-the-Loop Workflow)**.
* **Mandatory Field Sign-off:** Deliverables are provided on an "As-Is" architecture basis. Deployment onto live factory systems requires written validation by the partner's on-site **Certified Lead Automation Engineer**.
* **Merchant of Record (MoR):** All B2B transactions and digital asset sales are processed via **LemonSqueezy / Paddle** to guarantee automated compliance with global tax regulations (VAT, Sales Tax, GST).
